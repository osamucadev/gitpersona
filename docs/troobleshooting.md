# Git Access Troubleshooting — Private GitHub Organizations

## Context

Private GitHub organization with private repositories. User is a member of the org but unable to clone repositories via SSH or HTTPS.

---

## Issue 1: SSH Authentication Succeeds but Clone Fails

### Symptoms

```
ssh -T git@github.com
→ Hi <username>! You've successfully authenticated, but GitHub does not provide shell access.

git clone git@github.com:<org>/<repo>.git
→ ERROR: Repository not found.
→ fatal: Could not read from remote repository.
```

### Diagnosis

SSH authentication works correctly (the key is registered on GitHub and the correct user is identified), but the clone fails with "Repository not found" across **all** repos in the org — not just one.

Confirmed with:

```bash
git ls-remote git@github.com:<org>/<repo>.git
→ ERROR: Repository not found.
```

### Root Cause

Being a **member of a GitHub organization does not automatically grant access to all private repositories**. Repository access must be granted separately, either:

- By adding the user directly as a **collaborator** on the specific repository
- By adding the user to a **team** that has access to the repository

Additionally, some organizations enable **SSH key restrictions** at the org level, which require SSH keys to be explicitly authorized for the organization via SSO (SAML). If this is the case, the "Configure SSO" button appears next to each key in **Settings → SSH and GPG keys**.

> **Note:** It is possible to view a private repository in the browser while still being unable to clone it via SSH. Browser access and Git access use different permission layers.

### Checklist for the Admin

1. Go to `github.com/<org>/<repo>` → **Settings → Collaborators and teams**
2. Confirm the user appears with explicit permission (Read, Write, or Admin)
3. Check `github.com/organizations/<org>/settings/security` for SSH key restrictions

## Issue 2: HTTPS Clone Fails Due to Broken Credential Helper

### Symptoms

```
git clone https://github.com/<org>/<repo>.git

<path-to-custom-helper>.exe get: No such file or directory

Username for 'https://github.com': <username>
Password for 'https://<username>@github.com':
remote: Invalid username or token. Password authentication is not supported for Git operations.
fatal: Authentication failed
```

### Root Cause

Two problems occurring simultaneously:

1. **Broken credential helper**: Git was configured to use a custom credential helper that no longer exists at the configured path
2. **Password auth not supported**: GitHub stopped accepting passwords for Git operations. A **Personal Access Token (PAT)** is required

### Fix — Reset the Credential Helper

```powershell
# Check what helpers are configured
git config --global --get-all credential.helper

# Remove all custom helpers
git config --global --unset-all credential.helper

# Set Windows Credential Manager as the default helper
git config --global credential.helper manager
```

---

## Solution: Clone via HTTPS with Personal Access Token (PAT)

### What is a PAT?

A Personal Access Token is a string generated by GitHub that acts as a password for Git operations over HTTPS. GitHub no longer accepts account passwords for this purpose.

### Step 1 — Generate a PAT

1. Go to **github.com → Settings → Developer settings → Personal access tokens → Tokens (classic)**
2. Click **Generate new token (classic)**
3. Give it a descriptive name
4. Set expiration as needed
5. Check the **`repo`** scope
6. Click **Generate token**
7. **Copy the token** — it is only shown once

### Step 2 — Clone the Repository

```bash
git clone https://github.com/<org>/<repo>.git
```

When prompted:
- **Username**: your GitHub username
- **Password**: paste the PAT (e.g., `ghp_xxxxxxxxxxxx`)

### Step 3 — Token is Saved Automatically

Windows Credential Manager stores the token after the first use. Subsequent `git pull`, `git push`, and clone operations will work without prompting again — until the token expires.

## Summary Table

| Method | Result | Reason |
|--------|--------|--------|
| SSH clone | ❌ Repository not found | Org-level SSH restriction or missing repo permission |
| HTTPS with password | ❌ Auth failed | GitHub no longer accepts passwords |
| HTTPS with broken helper | ❌ Helper not found | Custom credential helper path invalid |
| HTTPS with PAT | ✅ Success | Correct authentication method |

---

## Notes for Future Reference

- The PAT expires after the configured period. Generate a new one when it expires and paste it when Windows prompts again
- If SSH needs to work in the future, the org admin should check whether SSH key authorization for SSO is required under the org security settings
- If building a custom Git credential helper, store the PAT in the system keyring and ensure the helper binary path remains valid across rebuilds and relocations
